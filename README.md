# PT2 Grader — 記述式試験答案のRAG自動採点システム

浸透探傷試験（PT）の記述式問題を対象に、教材コーパスの**ハイブリッド検索（ベクトル + BM25）**と
**ルーブリックに基づくLLM採点（Claude API・構造化出力）**を組み合わせた自動採点・添削アプリです。
観点別の得点、解答からの根拠抜粋、不足論点、教材の出典ページまでを返します。

**🔗 公開デモ: https://pt2-grader-demo.streamlit.app/** — ログイン不要。検索とmock採点は自由に試せます。
AI採点（Claude API）のみ合言葉が必要です（運営者のAPIクレジット保護のため）。
※ 無料ホスティングのため、しばらくアクセスがないとスリープします。起動ボタンが出たら押して1〜2分お待ちください。

## 特徴

- **2系統クエリのハイブリッド検索**: 問題文で「必要論点」を、解答文で「記述の裏取り」を
  それぞれ検索してマージ（ベクトル0.6 + BM25 0.4、min-max正規化）
- **出典の捏造防止**: 出典ページはLLMに書かせず、LLMは「使った資料の番号」だけを選択。
  実際の出典情報は検索チャンクのメタデータからコード側で構成
- **厳格な採点設計**: 観点ごとに解答からの根拠抜粋（evidence）を必須化。
  抜粋できなければ不正解扱い。合計点はLLMの申告値ではなくコード側で再計算
- **構造化出力**: 採点結果はPydanticスキーマで検証されたJSON。壊れた出力は境界で弾く
- **測定に基づく改善**: 人間採点との一致度（MAE / 観点一致率 / Cohen κ）を物差しに、
  1変更ずつ効果を実測して改善（下記）

## 評価と改善の軌跡

人間採点（ブラインド記入した正解データ）とシステム採点の一致度で品質を測定しています。

| 段階 | 変更内容 | Cohen κ | 備考 |
|---|---|---|---|
| ベースライン | ルールベースのキーワード判定（mock） | 0.458 | 言い換え表現に弱い |
| LLM採点導入 | Claude（claude-sonnet-5）+ RAG + 構造化出力 | 0.891 | 偽陽性（甘い採点）が残存 |
| エラー分析→改善① | 複数論点を束ねた採点観点を中核/細部に分割 + 判定閾値ルールをプロンプトに追加 | 0.891* | 偽陽性を全件解消（誤りの方向を安全側に統一） |
| エラー分析→改善② | 判定基準を「観点の主旨」ベースに精緻化・口語的言い換えを許容 | **0.927** | 偽陰性も削減 |
| 正解データの基準統一 | 人間採点側の判定揺れ4件を修正 | 1.000 | 現評価セット（15答案×22観点）を解き切り |

*観点分割の前後で評価の観点構成が変わるため、分割前の数値と直接比較はできません。
数値は実運用コーパス（市販教材、非公開）での実測値です。合計点のMAE（平均絶対誤差）は
最終的に20点満点で0.00点。改善の各段階は「測定 → エラー分析 → 1変更 → 再測定」の
サイクルで行い、全実験を記録しています。

## アーキテクチャ

```
解答テキスト ─┐
問題文 ────┼→ ハイブリッド検索（e5-small埋め込み×Chroma + BM25×SudachiPy）
             │      └ 2系統の検索結果をマージ（top-k=8、検索評価で実測選定）
             ↓
　ルーブリック(JSON) + 検索チャンク + 解答 → プロンプト組み立て
             ↓
　Claude API（構造化出力: 観点別判定・根拠抜粋・使用資料番号）
             ↓
　スキーマ検証 → 配点再計算 → 出典をメタデータから構成 → 結果表示/履歴保存
```

## 動かしてみる（デモデータ同梱・APIキー不要でも検索と採点の流れを体験可能）

```bash
git clone https://github.com/yuna2yuna/pt2-grader-space.git
cd pt2-grader-space
pip install -r requirements.txt
streamlit run app.py --server.address localhost
```

データ未設定の場合は同梱の**自作デモ教材**（`demo_data/`、著作物を含まない書き下ろし）で
自動起動します。初回はインデックス構築（埋め込みモデルのダウンロード含む）が走ります。

- **mock採点**: APIキー不要・無料。キーワード判定の簡易採点で、検索と画面の流れを体験できます
- **AI採点**: 環境変数 `ANTHROPIC_API_KEY` を設定すると Claude による本採点が動きます

デモ問題に貼り付けて試せる解答例:

> 浸透探傷試験は毛細管現象できずの中に浸透液が浸み込むことを利用する。手順は前処理、浸透処理、除去処理、現像処理、観察の順で行う。検出できるのは表面に開口したきずだけで、内部のきずには浸透液が入れないため検出できない。

## 環境変数

| 変数 | 用途 |
|---|---|
| `ANTHROPIC_API_KEY` | Claude APIでのAI採点に必要 |
| `PT2_DATA_DIR` | データディレクトリの明示指定（省略時: `data/` → 無ければ `demo_data/`） |
| `PT2_HF_DATA_REPO` | 実運用時: 教材を置いた private Hugging Face Dataset のリポID |
| `HF_TOKEN` | 上記 Dataset の read/write トークン（採点履歴の永続化にも使用） |
| `APP_PASSWORD` | アプリ全体のパスワードゲート（実運用時） |
| `API_KEYWORD` | AI採点だけを合言葉で保護（公開デモ用） |

## 実運用の構成（実教材データは非公開）

実運用では著作権のある市販教材をコーパスにするため、**このリポジトリにデータは一切含まれません**。
教材チャンク・ルーブリック・採点履歴は private な Hugging Face Dataset に置き、
アプリが起動時に取得します（構築済み検索インデックスも同Datasetに自動保存され、
2回目以降の起動を高速化）。秘密情報はすべてホスティング側のSecretsで注入します。

## 技術スタック

| 領域 | 採用技術 |
|---|---|
| 言語 | Python 3.11+ |
| 埋め込み | intfloat/multilingual-e5-small（ローカル実行・API費用ゼロ） |
| ベクトルDB | Chroma |
| キーワード検索 | rank_bm25 + SudachiPy（Mode C・正規化形） |
| RAGフレームワーク | LlamaIndex |
| LLM | Claude（claude-sonnet-5）・構造化出力（messages.parse + Pydantic） |
| UI | Streamlit |
| 評価 | 自作（MAE / 観点一致率 / Cohen κ、検索側は Hit@k / MRR / 観点カバー率） |

## データと著作権について

- `demo_data/` は本プロジェクトのために書き下ろした自作テキストで、市販教材からの
  転載・翻案を含みません
- 実運用コーパス（市販教材）・実ルーブリック・評価用の解答データは非公開です
- README記載の評価数値は非公開の実運用コーパスでの実測値です
